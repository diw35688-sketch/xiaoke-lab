# asr_demo —— 语音实验记录智能体

> 面向高校实验与学习场景的**具身语音智能体**：对着麦克风"说"出实验过程，系统听懂、结构化记录、追问确认、按方案核对，全程不用动手打字。

中国科学技术大学「107杯」智能体开发大赛项目。

---

## 它解决什么问题

做实验时手是湿的、戴着护目镜、盯着操作台，不方便停下来打字记录。这个系统让你**边做实验边口述**：

```
你：先加 5 毫升缓冲液，然后加热到 60 度……
系统：听懂了，结构化记录成一条条实验事件；缺信息会追问，疑似听错会确认。
```

核心价值：**让"记录"从"事后补、手动敲"变成"边做边说、自动结构化"**，实验过程和原始口述都完整可追溯；在「方案实验」模式下，还能**按选定方案一步步走，确定性核对数据对不对、缺不缺**。

---

## 对实验人员的价值

**一句话：让实验人员把精力放在"做实验"上，而不是"记实验"上。**

| 价值 | 说明 |
|---|---|
| 🖐️ 解放双手 | 手湿、戴手套、戴护目镜也能记录，口述就行，不用碰键盘 |
| ⏱️ 不打断节奏 | 边做边说，记录和操作并行，实验节奏不被"停下来打字"打断 |

| 📊 自动结构化 | 口述自动变成"操作/观察/测量/异常"条目，写实验报告、复核数据都省事 |
| 🛡️ 方案把关 | 方案实验时系统确定性核对数据对不对、缺不缺、偏差，防漏步骤、防记错数 |
| ⚠️ 安全提醒 | 涉及危化品/危险操作时给安全提示 |

## 设计创新点

### 1. 统一 Turn 协议：一套合同收拢三种交互

「自由聊天 / 自由实验 / 方案实验」本质上是同一件事——**一次"输入 → 理解 → 落盘 → 呈现"的往返**。项目把它们收拢成**一套 `Turn` 数据合同**（`turn_request → turn_result`）：

- 后端只有一个编排服务（`turn_application_service`）+ 两个处理器（聊天 / 实验）；
- 前端只有一个时间线事实源（`conversation_turn_store`）+ 一个传输客户端（`turn_client`）；
- 新增一种交互，不需要再复制一套链路，只需在合同上加字段。

### 2. 语音受控靠"确定性格式化器"，不靠 prompt

系统对用户"**说什么、用什么语气、按什么节奏说**"，由**确定性规则**（`presentation_copy` 文案、`spoken_output` 语音规划、播放调度）决定，而不是让大模型自由发挥。这样语音输出稳定、可测试、不会"这次和上次说得不一样"——**大模型只负责"听懂"，不负责"决定怎么说"**。

### 3. 三列界面：实验区与对话并存

Web 端采用「左侧导航 + 中间实验区 + 右侧聊天框」三列布局。做方案实验时，**左边看步骤卡片、右边口述/听它念，两边同时**，不用来回切视图。

### 4. 非阻塞录音 + 背压（桌面终端）

录音和 LLM 理解**并行**：主线程只负责"录音 → 提交后台队列"，后台单线程按序执行"理解 → 落盘 → 执行"，结果算完当场显示——**说话不卡、不丢**。

### 5. 原始数据优先

模型的结构化推断**永远不覆盖原始 ASR 原文**；结构化失败时如实提示"原始记录已保存，结构化处理暂时不可用"，不谎称"已记录"。原始口述、结构化事件、确认记录分别落盘，可追溯。

### 6. 确定性完成判定

「方案实验」的步骤"做没做完、数据对不对、该不该追问"，由**确定性状态机**（`protocol_execution_state` + `protocol_completion_policy` + `protocol_navigation`）判定，不是大模型猜——结果可复现、可测试。

## 技术路线

### 分层架构

```text
┌─────────────────────────────────────────────────────────┐
│  前端（Web，原生 JS 无框架）                                │
│  三列 UI · turn_client · conversation_turn_store · 语音/文字  │
└───────────────────────────┬─────────────────────────────┘
                            │  HTTP / SSE / WebSocket
┌───────────────────────────▼─────────────────────────────┐
│  Web 服务层（FastAPI）                                    │
│  /turn  /chat  /record  /protocols  /community  /tts …    │
│  turn_application_service（统一 Turn 编排）                │
└───────────────────────────┬─────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────┐
│  领域逻辑层（src/core，纯 Python）                          │
│  统一理解(LLM) → 分派 → 采用 → 执行                        │
│  协议执行状态/导航/完成策略 · 澄清追问 · 播放调度 · 会话上下文  │
└───────────────────────────┬─────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────┐
│  存储层（SQLite）                                          │
│  turn_requests · lab_records · messages · 协议会话状态       │
└─────────────────────────────────────────────────────────┘
```

### 一次口述的数据流

```
浏览器录音 → 编码 WAV → SenseVoice 转写（ASR）
        ↓
  turn_application_service 接受 Turn
        ↓
  统一理解（DeepSeek LLM，精确命令 0 次 LLM 直达）
        ↓
  分派 → 采用 → 执行（创建追问 / 回答 / 暂缓 / 确认 / 结束确认）
        ↓
  确定性落盘（原始 ASR + 结构化事件 + 确认记录 + 协议状态）
        ↓
  呈现（三列时间线渲染 + 语音 TTS 播放）
```

### 分层原则（架构核心）

- **机制与业务分离**：后台队列 `OrderedTaskQueue` 是通用"传送带"（不认识任何业务词），业务工人 `UnifiedSegmentProcessor` 是"装配工"——换领域可复用队列、不重写。
- **原始数据优先**：模型推断永不覆盖原始 ASR 原文。
- **高风险必确认**：结束、状态写入等高风险动作有明确边界，不靠模型猜。
- **外部失败不破坏核心**：LLM / ASR / TTS 任一失败，已完成的核心工作不回滚。

## 快速开始

Windows 新用户先安装 **Python 3.11 64 位**（勾选 `Add python.exe to PATH`），然后双击仓库根目录的 **`start.bat`**。首次运行会自动创建虚拟环境、安装依赖并下载语音识别模型；以后仍双击同一个文件即可。

项目目录可以移动、改名或放在其他盘符，启动器会按 `start.bat` 自己的位置寻找项目。API 密钥请在网页设置中填写，不要把 `.env` 或 `web/settings.json` 发给别人。

完整的新手步骤、体检命令、失败排查和交付边界见：[一键启动与转交指南](docs/ONE_CLICK_START_GUIDE.md)。

## 项目结构（关键文件）

```text
src/                          # 领域逻辑与桌面终端（纯 Python）
  main.py                     # 桌面终端入口：组合根 + 主循环
  audio/                      # 唤醒、VAD、录音、提示音
  asr/                        # 模型无关 ASR 后端
  llm/                        # 模型访问层
  core/                       # 领域逻辑层
    conversation_turn.py      # 统一 Turn 数据合同
    unified_understanding.py  # 统一理解输出合同
    protocol_execution_state.py / protocol_navigation.py / protocol_completion_policy.py
                               # 方案实验：执行状态 / 导航 / 确定性完成判定
    clarification_executor.py # 追问/回答/暂缓/确认执行
    ordered_task_queue.py     # 通用后台队列（机制层）
    unified_segment_processor.py # 六步业务流水线（业务层）
  storage/                    # JSONL 持久化
  wakeword/                   # 唤醒词检测（sherpa-onnx）

web/                          # Web 端（FastAPI）
  app.py                      # 应用组合根 + 三列前端注入
  turn_application_service.py # 统一 Turn 编排（接受→理解→落盘→呈现）
  turn_processors.py          # 聊天 / 实验两个处理器
  api/                        # HTTP 路由（turn/chat/record/protocols/community…）
  database/                   # SQLite（turn_store / 会话 / 协议状态）
  frontend/                   # 原生 JS（turn_client / conversation_turn_store / 三列 UI）
  asr_application_service.py  # 语音识别服务
  playback_runtime.py         # 统一语音播放授权

tests/                        # 单元 + 集成测试
docs/                         # 文档（任务清单/架构/交接等）
```
