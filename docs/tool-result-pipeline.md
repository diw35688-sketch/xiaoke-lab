# 实验助手：工具结果展示管道重构

## 目标

把当前“模型负责决策 + 长篇复述，代码用硬路由/提示词补丁救场”的架构，
改成成熟 Agent 产品的分层结构：

```text
用户输入
  ↓
模型：判断意图，选择工具（不负责最终长文）
  ↓
工具：读/写领域状态
  ↓
展示层：把工具结果转成结构化 UI（卡片/清单/步骤/流程/记录）
  ↓
模型文本：只写短确认/自然对话，不复述工具数据
```

## 核心原则

1. **工具是第一公民**：结果先成为结构化 UI，再考虑文字。
2. **展示层统一**：所有工具通过同一套 `present` 契约生成卡片。
3. **模型文本与工具结果分离**：有结构化结果时，正文不重复数据。
4. **不做关键词硬路由**：不让代码按“用户说了什么”分支到不同流程。
5. **提示词保持稳定**：不加“你必须短/你必须调用某工具”这类补丁。
6. **状态集中**：实验方案、步骤、试剂配制分支、清单、记录统一到会话状态。

## 当前差距

- 工具结果已能生成卡片，但模型仍会复述。
- 存在多个 Processor（Chat/Experiment/Template/Storage），行为不一致。
- 准备清单、试剂配制分支分散在多个 API/页面。
- 之前为压制长文添加了多轮硬编码补丁，应沉淀为统一展示层。

## 第一阶段（本次开始）

### 1. 统一“只读/搜索工具”的正文生成

规则：

```text
当一轮调用只包含 read/search 工具时：
  正文 = 每个工具卡片的第一行摘要 + “完整内容见工具卡片”
  替换模型长篇复述

当包含 execute/write 工具时：
  保留模型自然回复
```

这不是按功能写路由，而是一条输出层通用规则：
工具卡片已经承载数据，正文只取第一行作为确认。

### 2. 建立第一版 Artifact 合同

工具卡片现在同时携带 `artifact`：

```text
version / type / tool / title / status
summary / lines / actions / data
```

旧的 `title/lines/ui_action` 字段仍保留，保证现有前端兼容；新的聊天渲染优先消费
artifact 中的标题、内容和动作。这样后续聊天、实验画布、记录本可以共享同一个结果合同。
