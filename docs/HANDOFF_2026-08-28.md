# HANDOFF 2026-08-28 —— 语音理解"体感提速"（流式首 token 信号）

> 状态：**方案已设计、待白天实现**。本文件是白天接手的唯一起点，方案细节与代码位置都在这里。

## 一句话现状

实测一条中文语音 Turn 全程 7.66s = ASR 2.77s + 统一理解 4.86s + 落盘 13ms。
大头是 LLM（`deepseek-v4-flash`），慢的根源不是选错模型，而是：**非流式** `generate_json`
必须等完整 JSON 返回，前端在 LLM 阶段只能看到笼统的"正在理解内容…"，用户点完录音到首个
有效反馈之间约 4.86s 无变化。

选定目标：**体感提速**——LLM 首 token 一到就推"模型已响应"，感知等待从 ~4.86s 缩到 ~1.5s。
**不缩短总耗时**（模型生成完整 JSON 的时间不变）。

## 白天要做的：流式首 token 信号（6 处改动）

**核心机制**：用 `contextvars.ContextVar` 作为跨层通道，把"首 token 到达"从最内层
`WebSettingsLLMClient.generate_json` 冒泡到最外层 `TurnApplicationService` 的进度对象，
触发新增的 `responding` 进度阶段。流式写法参考项目已有 `web/agent/core.py:189-210` 的
`stream_agent`。

为什么用 ContextVar 而非显式传参：首 token 要跨 6 层（prepare→observe→inspect→route→
understand→generate_json），显式传参要改 6 个签名、波及 `src/main.py`、`unified_dispatch_bypass`
和 20+ 测试；ContextVar 改动收敛在 2 个文件，是 FastAPI/Flask 同款惯用法。turn 在独立线程池
同步调用栈内 set/get 同一线程，线程安全。

### 改动清单

1. **`src/llm/client.py`**：`LLMGenerationResult`（第 37-45 行）新增可选字段
   `first_token_seconds: float = 0.0`（默认值保证现有 FakeClient 测试不受影响）。

2. **`web/llm_bridge.py`**：
   - 顶部新增 `from contextvars import ContextVar` 和
     `first_token_hook: ContextVar = ContextVar("llm_first_token_hook", default=None)`。
   - `WebSettingsLLMClient.generate_json`（第 35-83 行）改 `stream=True`，迭代 chunk 拼
     content（`if not chunk.choices: continue` → `delta.content`），首 token 时记
     `first_token_seconds` 并触发 `first_token_hook.get()`（若存在）。保留重试循环与
     `processing_seconds`；`first_token_seconds` 只取最终成功那次的首 token。

3. **`web/turn_application_service.py`**：`_execute_prepared`（第 211-253 行）里
   `progress.publish("understanding")`（第 218 行）之后、`processor.prepare(turn, timing)`
   （第 219 行）之前，`token = first_token_hook.set(lambda: progress.publish("responding"))`，
   用 `try/finally` 复位。

4. **`web/turn_stream_contract.py`**：`TURN_STATUS_PHASES`（第 8-15 行 frozenset）加
   `"responding"`，否则 `turn_status_event` 会抛 `ValueError`。

5. **`web/api/turn.py`**：`_STATUS_TEXT`（第 35-42 行）加 `"responding": "模型已响应…"`。

6. **前端零改动**：`turn_client.js` 的 `consume`（第 179 行）与 `mobile.js`（第 226-228 行）
   都只读 `event.text`，文案由服务端 `_STATUS_TEXT` 提供。

## 收益与边界

- 收益：感知等待 ~4.86s → ~1.5s；顺带获得 `first_token_seconds` 测量，为后续"精简 prompt"
  （真实降总耗时）提供数据依据。

  （`run_agent`/`stream_agent`）不纳入，但同一 ContextVar 机制可复用。
