# 今晚对话收获 · 2026-08-14

> 这是一份"对话收获"记录，不是项目技术文档。记的是今晚这一场对话，我们从哪里出发、一路挖到了什么、学到了什么。
> 目的：以后回看能想起"今晚我们到底想通了几件事"。

## 一句话总结

今晚从一句"**终端输出看不出用户体验如何**"出发，一路挖到了项目里最深的**三笔假账、两句谎话、一个偷换概念**，并且给每一类问题都立了**防止再犯的机制**。

---

## 一、今晚走过了什么（脉络）

1. 用户提了一个根本问题：**agent 只验收"能力有没有实现"，不验收"用户体验如何"，两边都说不清。**
2. 于是建立**九维体验走查机制**，跑了一次基线走查，抓出 8 项体验问题。
3. 用户一路追问：提示音、嘈杂识别、用户版/管理员版、"不做 PRESENT 怎么知道现在工作有没有用"、"反过来 GAP 会不会返工"。
4. 用户点破：**"每次都说是必修问题"** → 逼出了"硬问题/软问题"判据和"硬问题清零即进 PRESENT"的闸门。
5. 用户要求**回顾新路** → 先按天整理，再被逼着讲"价值" → 用"4 个病"讲清楚。
6. **用户扮面试官**，10 个拷问 → 揭穿"两次调用"是偷换、数据安全那个 bug 是自己引入的、答辩只守得住"数据安全"一点。
7. **用户本人继续深挖** → 揭穿：旧路本来也是一次调用、新路初心是"LLM 语义兜底"但验证不足（7 缺口）、"跳过"没恢复、"中风险弃权"过度保守。
8. **用户再扮评委查代码** → 挖出铁证：`main.py` 还留着"无需等待 LLM"的谎话、非阻塞录音能力丢了却没登记。
9. 最后"全扫一遍"文案 → 抓出 **2 句谎话 + 2 处误导 + 一批 DEBUG 泄漏**。

## 二、项目层面：挖出了什么真问题

### 三笔此前漏记的债

| 债 | 是什么 | 严重度 |
|---|---|---|
| **非阻塞录音丢失** | 旧路靠后台线程+队列，用户"说完继续说、连续口述不卡"（真机验收过"连续5段不卡"）；新路改成同步串行，说完要干等 LLM 算完（2.6s~10.98s）。这个能力被删了，却**没登记任何恢复任务**。 | **P0 硬问题** |
| **降级人话提示丢失** | LLM 失败时，用户现在看不到"原始记录已保存"，只看到一行开发日志，会以为系统崩了。 | P1 |
| **文案与实际行为不一致** | 删代码时只删代码、不改还在引用旧行为的文案。 | P1 |

### 两句谎话（"说给用户的话"和实际行为不符）

1. `main.py:320`：**"现在可以连续口述，无需等待 LLM 处理完成。"** → 实际是同步等待。
2. `main.py:111`：**"观察失败…；旧流程继续。"** → 旧流程已经删了，没有旧流程接手。

### 一个假账

`PROJECT_ARCHITECTURE.md` 5.3 表把"后台线程/队列/背压"写成**"无后台任务，无需等待 = 等价（无此需求）"**——把"用户可感知能力丢失"写成了"不需要"。这是继下面那条之后，第二个事实错误。

### 一个偷换概念

文档和答辩里的头号卖点"**旧路两次 LLM 调用、新路省一半**"是**偷换**：旧路本来就是"本地精确规则（零 LLM）+ 一次结构化 LLM = 一次调用"。"两次调用"只出现在①被否决的对比实验里、②双轨并行期。**把被否决的方案当成了旧路。**

### 一个没兑现的初心

新路的真实动机本来是"**ASR 识别错/模糊口述时，LLM 语义能接住**"（容错）。但验证结果是鲁棒性评测 **21/28 一致、7 缺口**；而且"跳过"（暂缓）能力没恢复、"中风险弃权"把可逆的"跳过"也挡在门外——**方向对，但核心能力没兑现，还被过度保守阉割了一部分。**

## 三、方法层面：建立了什么机制

| 机制 | 解决什么问题 | 位置 |
|---|---|---|
| **九维体验走查** | 功能验收（REAL_OK）≠ 体验验收（UX_CONFIRMED），体验最终裁决权在用户 | `docs/UX_WALKTHROUGH_CHECKLIST.md` |
| **硬/软问题判据** | 阻止"每次都标必修"——用"用户能否完成实验并拿到正确数据"做客观分界 | 任务清单第 1 节 |
| **推进闸门** | 硬问题清零即进 PRESENT，不设固定日期；软问题与 PRESENT 并行 | 任务清单第 1 节 |
| **迁移对照含体验质量** | 阻止"动作迁移了、体验质量退化了却没人发现"——逐项标等价/降级/丢失 | `PROJECT_ARCHITECTURE.md` 5.4 |
| **UX 价值追踪表** | 回答"当前工作对体验有没有用"——每项 UX 问题都有归属任务 | 走查表 7.5 |
| **SYNC-UI-CLAIMS** | 文案与行为一致性核查——抓住测试和判据都拦不住的"承诺≠实际" | 任务清单第 17 项 |
| **对话表达规范** | agent 回复分层清晰、术语必解释、不催用户 | `CLAUDE.md` |

## 四、认知层面：学到了什么教训

### 教训 1：价值叙事要回到初心，不能掺假
"省调用"是偷换、"数据门卫"那个 bug 是自己引入的、"468 测试"护规格不护价值。**唯一没塌的，是"数据不丢、不被写错"这一条，而且它还有真实 bug 背书。** 讲价值时，砍掉站不住的，只留经得起追问的。

### 教训 2：重构的两个经典坑
- **删代码不改文案 = 说谎**（"无需等待"、"旧流程继续"）；
- **把能力丢失写成"无此需求" = 假账**（非阻塞录音）。

### 教训 3：验收体系有盲区
468 测试、REAL_OK、九维走查、硬软判据——**全都没拦住"承诺≠实际"**，因为它不是崩溃、不是数据错、不是显示丑。这类问题只能靠"逐条核对用户看到的话 vs 真实行为"来抓。**真正懂验收的人，是那个一直在替用户读终端、替用户感受的人。**

### 教训 4：答辩/总结的正确姿态
**先认丑，再讲守住的那一点。** 把站不住的全砍掉，只留一句经得起三连问的话。最有杀伤力的不是"我多好"，而是"我把我哪里不好，先说出来"。
