  一、先给结论

  文字 / 录音 / 通话  →  汇合成 TurnInput（漏斗收口）

  1.1 这一章解决什么真实问题

  以前"打字"和"录音"是两套不同格式的数据进系统，聊天和实验又是两套保存逻辑。结果

  这一章干的事：定义一个统一的数据结构 TurnInput，规定"不管用户是打字还是说话、
  是聊天还是实验，进入业务前都必须先装进这个同一个模子"。模子上还有验票口（不变
  条件），不合格的直接拦在外面，不进入业务。

  ---
  1.2 先补 5 个前置概念（零基础必须懂）

  概念 1：dataclass（数据类）

  白话：想象你要填一张表，表上有"姓名、电话、地址"几个栏目。普通写法，你得手写一
  个 __init__ 方法把这三个值一个个塞进去，还要手写 __eq__
  才能比较两张表是否一样。@dataclass
  这个装饰器就是让你只声明"有哪些栏目"，Python 自动帮你生成这些样板方法。

  术语：装饰器（decorator）+
  数据类（dataclass）。装饰器可以理解为"给函数/类加一层自动加工"。

  反例：不用它，下面这个类你要手写 8 行 self.xxx = xxx，容易漏。

  概念 2：frozen=True（冻结 / 不可变）

  白话：frozen=True
  表示这个对象建好之后就不能再改，像被冻住了。想改任何一个字段都会报错。

  为什么这里要用：TurnInput
  是"用户当时说了什么"的证据快照。如果中途能被改，就会出现"数据库存的是
  A，业务读到的是 B"这种对不上的账。冻结 = 证据不会被偷偷篡改。

  术语：不可变对象（immutable object）。

  概念 3：Enum（枚举）

  白话：枚举就是"只能从几个固定的选项里挑一个"的取值方式。比如"星期"只能是周一到
  周日这 7
  个值，不能填"星期八"。用枚举，编译器/运行时就能帮你挡住"手滑写错的值"。

  反例：如果用普通字符串 mode: str，有人可能写
  "caht"（拼错了），系统认不出来也不报错，一路传到后面才炸。枚举在入口就拦住。

  概念 4：__post_init__（初始化后的验票口）

  白话：dataclass 会自动生成 __init__（把值塞进字段）。__post_init__
  是在塞完值之后、对象正式交给别人用之前，自动跑一次的检查函数——像进火车站前的验
  票口，票不合格就当场拦下。

  术语：不变条件校验（invariant validation）。不变条件 =
  这个对象从头到尾都必须成立的规矩。

  概念 5：str | None（联合类型 / 可空）

  白话：lab_session_id: str | None
  意思是"这个字段要么是一个字符串，要么是空（None）"。竖线 | 表示"或"。

  为什么这么写：实验模式必须有 lab_session_id，但聊天模式没有实验会话，所以允许
  它是空的。类型标注里先声明"可能为空"，真正"什么时候必须非空"由 __post_init__
  判断。

  1.5 逐段讲 __post_init__（验票口），对应文档 4 条失败场景

  代码在 turn_input.py 第 37–81 行。我按顺序逐段讲，每段标注它对应文档第 6 
  节哪条失败场景。

  第一段：三个 ID 必须是非空字符串（第 38–40 行）

  38      for field_name in ("conversation_id", "request_id", "turn_id"):
  39          _require_non_blank(getattr(self, field_name), field_name)
  40      _require_non_blank(self.raw_text, "raw_text")

  _require_non_blank 在文件第 15–19 行，它干两件事：不是字符串就抛
  TypeError，是字符串但去空格后为空就抛 ValueError。

  白话：conversation/request/turn 三个 ID 和原话，不能是空的、不能只塞一个空格。
  少了它们，后面连"这条数据属于谁、是什么"都说不清。

  第二段：类型必须是枚举（第 42–45 行）

  42      if not isinstance(self.interaction_mode, InteractionMode):
  43          raise TypeError("interaction_mode 必须是 InteractionMode。")
  44      if not isinstance(self.experiment_context, ExperimentContext):
  45          raise TypeError("experiment_context 必须是 ExperimentContext。")

  白话：这两个字段不能传个 "chat" 字符串或 123
  糊弄，必须是真正的枚举对象。这对应概念 3 说的"入口就拦住手滑值"。

  第三段：模式与上下文的配对规则（第 46–57 行）—— 对应失败场景"Chat 
  带实验上下文，或实验未选 free/protocol"

  46      if self.interaction_mode == InteractionMode.CHAT:
  47          if self.experiment_context != ExperimentContext.NONE:
  48              raise ValueError("chat 模式的 experiment_context 必须是 
  none。")
  49          if self.lab_session_id is not None:
  50              raise ValueError("chat 模式不能携带 lab_session_id。")
  51      else:
  52          if self.experiment_context not in {
  53              ExperimentContext.FREE,
  54              ExperimentContext.PROTOCOL,
  55          }:
  56              raise ValueError("实验模式必须选择 free 或 protocol 上下文。")
  57          _require_non_blank(self.lab_session_id, "lab_session_id")

  白话：这是"身份一致性"检查。
  - 如果模式是 chat：实验上下文必须是 NONE，且不能带
  lab_session_id（聊天没有实验会话）。
  - 否则（experiment）：实验上下文必须在 free 或 protocol 里选一个（不能是
  NONE），且 lab_session_id 必须有值。

  反例（不知道会怎样）：如果没有第 49–50 行，就可能出现"聊天却带了个实验会话
  ID"，后端把它写进实验表，聊天和实验数据串在一起。

  第四段：mode_version 必须是正整数（第 59–64 行）

  59      if not isinstance(self.mode_version, int) or isinstance(
  60          self.mode_version, bool
  61      ):
  62          raise TypeError("mode_version 必须是正整数。")
  63      if self.mode_version <= 0:
  64          raise ValueError("mode_version 必须是正整数。")

  注意第 59–60 行有个细节：isinstance(True, int) 在 Python 里是成立的（因为 bool
   是 int 的子类）。所以代码特意把 bool 也排除掉，防止有人传 True/False
  冒充整数。这是很容易漏的坑。

  第五段：输入来源与 ASR 证据的配对（第 66–81 行）—— 对应其余 3 条失败场景

  66      if not isinstance(self.input_source, InputSource):
  67          raise TypeError("input_source 必须是 InputSource。")
  68      if self.asr_result is not None and not isinstance(
  69          self.asr_result, ASRResult
  70      ):
  71          raise TypeError("asr_result 必须是 ASRResult 或 None。")
  72
  73      if self.input_source == InputSource.TEXT:
  74          if self.asr_result is not None:
  75              raise ValueError("文字输入不能携带 ASR 证据。")
  76          return
  77      if self.asr_result is None:
  78          raise ValueError("语音输入必须携带 ASR 证据。")
  79      if not self.asr_result.is_final:
  80          raise ValueError("语音输入必须携带最终 ASR 证据。")
  81      if self.raw_text != self.asr_result.asr_transcript:
  82          raise ValueError("语音 raw_text 必须与 ASR 忠实转写一致。")

  这段对应文档第 6 节的 4 条失败场景，我逐条对上：

  - 第 73–75 行 → "文字 Turn 上传 ASRResult：拒绝"。打字还带 ASR
  结果？说明客户端在伪造证据，直接拒绝。
  - 第 77–78 行 → "语音 Turn 没有最终 ASRResult：不进入业务处理"。语音必须有 ASR
   结果，没有就说明识别还没完成，不能进业务。
  - 第 79–80 行 → 语音的 ASR 结果必须是 is_final（最终版）。ASR
  有时会先返回"临时结果"再返回"最终结果"，这里只要最终的。
  - 第 81–82 行 → "ASR 文字与 raw_text
  不一致：拒绝"。这是最关键的防篡改规则：语音输入的 raw_text 必须等于 ASR
  的忠实转写。防止客户端自己把 raw_text 改成别的（比如把"加 5 毫升"改成"加 50
  毫升"）来覆盖模型的真实识别。

  这就是整个 TurnInput 的核心价值：语音路径里，raw_text 不是客户端说了算，而是被
   ASR 转写锁死的（术语叫"源可信 / source-truthful"）。

  1.6 to_wire() 是干什么的（第 83–99 行）

  83  def to_wire(self) -> dict[str, object]:
  84      return {
  85          "conversation_id": self.conversation_id,
  ...
  90          "input_source": self.input_source.value,
  ...
  95          "asr_result": (
  96              self.asr_result.to_dict() if self.asr_result is not None else
  None
  97          ),
  98      }

  白话：to_wire 是"把对象转成能传上网络/存库的普通字典"。注意它把枚举转成了
  .value（字符串），把 asr_result 转成了
  to_dict()。因为网络上和数据库里不能直接存 Python 对象，只能存字符串和数字。

  术语：序列化（serialization）。后面你会在 turn_store.py
  里看到，canonical_request_hash(turn.to_wire())
  就是先序列化成字典、再算哈希做幂等——第 1 章的 to_wire 正是那个哈希的输入。

  1.7 本章小结（白话收口）

  - TurnInput 是什么：一次交互的"统一模子"，10
  个字段装下"谁、哪次、什么模式、怎么输入、说了什么、ASR 证据"。
  - 它靠什么保证可信：frozen=True（不可改）+ __post_init__ 里 5
  段不变条件（验票口）。
  - 它最大的功劳：语音路径下，raw_text 被 ASR 转写锁死，客户端不能偷偷篡改。

  这一章里，你看到的软件工程概念有：dataclass、不可变对象、枚举、不变条件、序列
  化、联合类型、源可信。
