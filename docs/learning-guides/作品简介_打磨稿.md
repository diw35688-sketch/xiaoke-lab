# 「小科」作品简介打磨稿

> 用途：中国科学技术大学「107 杯」智能体开发大赛作品简介。  
> 状态：逐项打磨中，本文档只固化已确认内容。

## 一、作品名称

**「小科」——实验语音交互与流程辅助智能体**

> **让实验人员少停一次手、少漏一条数据，让每一句现场口述都能进入可继续、可核对、可追溯的实验流程。**

## 二、总体定位

「小科」是一款面向实验全流程的智能体。它以语音交互为核心，让实验人员在操作仪器、处理样品或佩戴手套时，可以直接口述实验现象、参数和控制指令；系统不仅能“听见”，还会结合当前方案和实验步骤理解内容，形成结构化记录，主动追问遗漏信息，并通过文字、卡片和语音及时反馈。

围绕一次实验的完整生命周期，「小科」进一步连接了实验方案、专业计算、试剂配置、安全提示、实验排期、样品与试剂储存、长期记忆和实验社区。实验人员可以从“准备怎么做”，一路走到“现场做了什么”和“结束后如何回看、复用与交流”，减少在纸笔、文档、计算器和多个管理工具之间反复切换。

它不是给输入框加上一层语音转写，也不只是在页面上展示几个 AI 回答，而是尝试让大模型的自然语言理解、确定性实验工具和可追溯记录共同参与真实实验过程。

### 作品亮点速览

- **能听**：支持单次录音、移动端录音和连续通话，兼顾实验现场的免手操作需求。
- **能懂**：从自然口述中识别操作、对象、数值、单位、温度、时长和控制意图，不确定时允许明确弃权。
- **能记**：同时保留原始识别结果和结构化实验记录，模型推断不覆盖用户原话。
- **能追问**：发现关键信息缺失时生成编号问题，多轮回答仍能补回对应记录。
- **能核对**：持续比较实验方案、当前步骤、现场参数和待确认事项，提示遗漏与偏差。
- **能执行**：连接计算、方案、排期、储存和记忆等真实工具，执行成功后再反馈结果。
- **能延续**：围绕实验会话组织步骤、记录和上下文，使交互不止停留在一次问答。
- **能复用**：方案和试剂配方可管理、检索、导入与交流，让一次实验经验成为后续可利用的资产。

## 三、作品背景

实验活动贯穿方案准备、现场操作、过程记录和结果复盘等多个阶段，涉及大量文档、数据、工具和人员协作。随着大模型和语音交互技术的发展，智能体开始具备理解自然语言、调用专业工具并持续参与工作流程的能力，为实验场景的数字化和智能化提供了新的实现方式。

然而，实验工作具有操作连续、信息专业、过程状态复杂和结果需要追溯等特点。通用对话模型或简单语音转写难以直接适应这些要求。如何让智能体真正进入实验流程，在不干扰现场操作的前提下可靠记录实验事实，并连接实验前后的方案、工具和资料，是本作品关注的主要方向。

除了做实验时的现场记录，实验人员还要编写方案、计算配液参数、准备试剂、安排实验、管理样品，以及整理和交流经验。如果这些工作始终分散在不同文档和工具中，智能体就很难真正参与完整的实验过程。因此，「小科」在突出语音记录的同时，也希望把实验前后的信息和工具组织起来。

## 四、解决的问题

1. **实验准备信息分散、工具入口不统一**

   实验方案、资料、试剂库存、参数计算、实验排期和仪器信息通常分布在不同文档与工具中，实验人员需要反复查找、核对和切换，增加了准备成本，也容易产生遗漏。

2. **实验操作与过程记录难以同步**

   实验人员在连续操作仪器、处理样品或佩戴手套时，不便使用纸笔和键盘。传统记录容易打断操作节奏，事后补记又可能造成步骤、参数和实验现象遗漏。

3. **自然口述难以直接形成完整、可靠的实验记录**

   普通语音转写只能生成文本，无法识别其中的操作、对象、用量和实验现象，也不能及时发现单位、温度或时长等关键信息缺失。多轮追问后，还需要将回答准确补充到对应记录中。

4. **实验方案与实际执行缺少持续核对**

   实验过程可能出现漏做步骤、参数偏差、顺序调整和多个待确认问题。普通单轮问答难以持续维护当前实验、执行步骤和待补信息，容易出现上下文丢失或回答错配。

5. **大模型生成能力与实验任务的可靠执行之间存在差距**

   通用大模型可以生成计算结果或声称「已经记录」「已经修改」，但不代表结果经过专业工具计算，也不代表业务操作真正完成。实验场景需要将语言理解与确定性计算、工具执行、结果校验和操作确认结合起来。

6. **实验资料、记录和经验缺少连续沉淀与协作渠道**

   实验完成后，原始口述、结构化记录、实验方案和交流经验容易散落在个人文件中，难以回溯、复用和共享，需要统一组织实验资料，并为方案复用、过程复盘和实验交流提供支持。

## 五、核心功能

作品以实验过程中的语音交互为核心，同时照顾实验前后的实际需求。实验前，它可以帮助创建方案、完成专业计算和试剂配置，并检查实验排期冲突；实验中，它负责语音记录、主动追问、方案核对和储存登记；实验后，相关记录、方案和经验还可以继续回看、复用和交流。

### 一次完整的使用体验

实验开始前，用户可以让「小科」查找或创建实验方案，计算溶液配制参数，查看试剂配置步骤和安全信息，并检查实验时间与仪器是否冲突。进入实验后，用户只需自然口述“加入 5 毫升缓冲液”“当前温度 37 度”或“问题一，十分钟”，系统就会识别语音、理解实验语义、写入对应记录并提示尚未补齐的信息。实验结束后，用户可以回看原始口述和结构化记录，将方案或试剂配方继续复用，也可以在实验社区中交流。

整个过程形成“**准备—执行—记录—核对—复盘—复用**”的连续闭环。


### 1. 实验过程语音记录与流程辅助（核心竞争力）

语音能力贯穿「听、懂、记、说」四个环节：

**听**——支持单次录音、移动端录音和连续通话。采集时用语音活动检测（VAD）配合 0.5 秒预录制缓冲，避免句首被截断；经 SenseVoice 语音识别转成文本，并同时保留原始识别输出与可信转写。

**懂**——先做零成本的精确规则匹配（如「结束记录」「问题一，十分钟」），命中的命令不调用大模型；其余口述由一次大模型调用同时完成意图判断、实体提取与控制识别，结果三选一：实验记录、控制命令、或明确弃权（说不准就不伪装成事实）。

**记**——原始口述先落盘，再写入结构化记录，模型推断不覆盖原始事实。自由实验和方案实验中，关键信息缺失时都会生成带编号的待回答问题，实验人员可通过「问题一，十分钟」这类编号回答，将补充信息准确归入对应记录。方案实验中实际参数与方案要求不一致时，保留实际口述并提示偏差，不擅自修改实验事实；模型调用失败时降级为仅保存原文，记录不丢失。

**说**——语音回复经过统一的播放授权，内容资格与运行时发声权限分离，只有获准的内容才会被朗读。

### 2. 配套功能

以下能力均通过语音或对话入口统一触达，与语音线协同：

#### 2.1 实验方案管理

内置结构化的实验方案库，每份方案拆解为带编号的步骤，并明确每步的现场必测参数、已知规定值与危险提示。在方案实验模式下，系统持续跟踪当前步骤、已记录参数和还缺字段，只有必测参数记齐且无偏差时才判定该步完成，也可由实验人员手动确认。实验人员还能用自然语言创建新方案、增删改步骤，系统自动校验并升级方案版本。

#### 2.2 专业计算

提供基础数学计算，以及面向实验配液的专业计算：按试剂名或化学式计算分子量/摩尔质量、按"浓度×体积×分子量"计算配制称样量、按 C1V1=C2V2 计算稀释所需母液体积。计算由确定性工具完成，结果只引用工具返回值，避免模型凭记忆给出不可靠数值。

#### 2.3 试剂配置与安全提示

维护通用试剂目录与危化品库，提供试剂的 CAS 号、分子式、GHS 危险性说明与高危提示。支持用自然语言创建和管理试剂配制方案（名称、目标浓度、溶剂、配制步骤、保存条件与有效期等），并在配液前确认试剂的形态、密度、纯度与目标 pH，对酸性试剂主动提醒调 pH。

#### 2.4 实验排期与冲突检测

实验人员可通过对话登记实验的起止时间与所用仪器，系统在创建前自动检测时间与仪器占用冲突；存在冲突时暂缓创建并给出提示，经用户明确确认后才写入，避免设备预约相互冲突。

#### 2.5 长期记忆与储存库

系统可将实验室长期稳定的信息（设备数量、预约规则、用户偏好、固定流程）在用户确认后保存为长期记忆，供后续对话引用。同时提供储存库，用于登记种子、样品、试剂、溶液等物品的名称、存放位置、数量与有效期，并统计临期与过期物品。

#### 2.6 实验交流

实验方案与试剂配方可以发布到社区，供成员浏览、检索与一键导入复用，为方案共享、经验沉淀和团队协作提供统一入口。

#### 2.7 多端交互与个性化配置

系统提供桌面端与移动端界面：桌面端适合方案、记录、储存和系统设置等综合管理，移动端适合实验台旁查看步骤、录入信息和进行语音交互。用户可以按设备和使用环境选择浏览器语音或服务端语音合成，并调整模型、音色、语速及相关服务配置。

#### 2.8 文档与资料辅助

系统预留并接入文档解析与文字识别能力，可配合 MinerU 和 OCR 从实验资料中提取文字，为后续生成方案草稿、整理实验信息和复用已有资料提供入口。专业资料进入系统后仍需经过结构化校验和用户确认，避免把模型生成内容直接当作实验事实。

## 六、使用的模型及 API 调用方式

**大语言模型（可自定义）**：统一理解与对话通过 OpenAI 兼容接口接入，模型地址（Base URL）、API 密钥和模型名均可在设置页修改、保存后立即生效；内置中科大 LLM、DeepSeek、OpenAI、通义千问等预设，并支持从 /models 接口拉取可用模型与一键测试连通性。密钥仅写入本地配置文件、不进入版本库，返回前端时始终掩码。

**语音识别（ASR）**：采用 FunASR SenseVoice（iic/SenseVoiceSmall），默认固定中文识别。

**语音合成（TTS，可自定义）**：支持浏览器内置、Edge TTS、OpenAI 兼容、阿里百炼 CosyVoice、本机 Qwen3-TTS、火山引擎豆包语音六种后端，音色与语速可调。

**其他辅助模型**：唤醒词检测（sherpa-onnx-kws）、语音活动检测（silero VAD）、文档解析（MinerU）与文字识别（OCR），与主链路解耦、可按需替换。

## 七、创新点

### 1. 从「停下来记录」到「边实验、边口述、边跟进」

传统实验记录要求实验人员中断操作，再使用纸笔或键盘输入。「小科」支持单次录音、移动端录音和连续通话，使实验人员在操作仪器、处理样品或佩戴手套时，也能通过自然口述同步记录实验过程。

系统不只把语音转换成文字，还会继续完成实验语义理解、结构化记录和结果反馈，使语音真正成为实验过程中的交互方式，而不是附加在输入框上的听写功能。

### 2. 从「被动记下」到「主动发现遗漏并追问」

普通录音和语音转写只能保留用户说过的内容，无法发现哪些信息没有说。「小科」能够识别实验口述中的操作、对象、用量、单位、温度和时长等信息；发现关键字段缺失时，会生成带编号的待回答问题。

这一设计使实验记录从「用户说多少就记多少」，转变为「系统主动帮助补齐关键信息」。实验人员可以在自由实验或方案实验中，通过「问题一，十分钟」等回答，将补充信息准确归入对应记录。

### 3. 从「照着方案看」到「方案与现场操作持续核对」

传统电子方案通常只是静态步骤列表，实验人员仍需自行判断当前做到哪里、参数是否完整。「小科」将实验方案与现场口述关联，持续维护当前步骤、方案要求、实际记录、待补字段和参数偏差。

当现场参数与方案要求不一致时，系统保留实际口述并提示偏差，不会为了让记录「看起来正确」而擅自修改实验事实。这使实验方案不再只是供人阅读的文档，而成为能够参与实验过程的动态参照。

### 4. 从「模型说完成了」到「实际执行后再反馈」

通用大模型可能生成「已经记录」「已经修改」或直接给出计算数值，但这些文字并不代表任务真正完成。「小科」将自然语言理解与记录、计算、方案和储存等真实工具连接，只有工具执行或数据提交成功后，才根据实际结果向用户反馈。

分子量、配液和稀释等数值任务由确定性计算工具完成；创建、修改和长期保存等操作引入确认机制。用户得到的不只是一个听起来合理的答案，而是可以检查的执行结果。

这种「先执行、后反馈」的方式不只用于实验记录和专业计算，也用于方案创建与修改、实验排期、储存登记和长期信息保存。因此，「小科」不只是回答实验问题，也能真正帮助实验人员完成部分具体任务。

### 5. 从「黑箱整理」到「原始事实可回看、失败也不丢记录」

大模型整理实验内容时可能出现误解或补写。如果只保存模型生成的结果，实验人员将难以确认自己当时究竟说了什么。

「小科」分层保存原始音频、ASR 转写、模型理解结果、结构化实验事件和确认状态，模型推断不会覆盖原始事实。即使模型服务暂时失败，系统也优先保留原始口述，并明确反馈当前处理状态，为实验复盘和错误核对留下依据。

### 技术设计支撑

为保证单次录音、移动端录音和连续通话获得一致的实验理解与记录体验，系统采用沙漏式统一 Turn 架构，将多种输入收敛为携带实验上下文的标准交互单元，再分派到不同业务处理器。大模型 Agent 负责理解自然语言、识别任务和选择工具，确定性工作流、状态机和业务规则负责模式隔离、缺失字段管理、方案完成判定、工具执行和结果提交，在自然交互与可控执行之间建立平衡。

这样一来，方案、记录、计算、储存和社区就不再只是几个互不相关的页面。实验人员可以先创建或复用方案，在执行过程中完成记录与核对，实验结束后再继续回看和交流，整个过程更加连贯。

「小科」希望呈现的，不是一次精心准备的固定演示，而是一种可以继续扩展的实验智能体工作方式：**用自然语言降低交互成本，用确定性工具保证关键结果，用完整记录保留实验事实，让 AI 真正走到实验台旁。**
